    Learn the concepts

    Short explanations for the ideas behind the simulator.

    What is a distributed system?

    A distributed system is a group of independent computers that work together and look like one system to the user. The computers talk only by sending messages over a network. Examples are online banking, cloud storage and multiplayer games.

    What is a logical clock?

    A logical clock is a counter, not a real clock. It does not tell the time of day. It only helps us decide which event came first when one event could have caused another.

    Why are physical clocks hard to synchronize?

    Every computer clock runs a little fast or slow (clock drift). Network delay is not constant, so one machine cannot know exactly what time another machine shows. Even small differences can put events in the wrong order.

    The Lamport clock algorithm

    Each process i keeps a counter C[i], starting at 0. Local event: C[i] = C[i] + 1. Send: increase C[i] by 1 and attach it to the message. Receive: C[j] = max(C[j], ts) + 1.

    Happens-before relationship

    We write a → b when a happened before b. This is true if (1) a and b are on the same process and a is earlier, or (2) a is the send of a message and b is its receive, or (3) a → c and c → b. If neither a → b nor b → a, the events are concurrent.

    Causal ordering

    Causal ordering means a cause is always ordered before its effect. Lamport clocks guarantee this: if a → b, then C(a) < C(b). A reply can never get a smaller timestamp than the message it answers.

    Limitations of Lamport clocks

    The reverse is not true: C(a) < C(b) does not prove a → b, because the events may be concurrent. Lamport clocks cannot detect concurrency. Two different events can also share the same timestamp, so ties are broken by process id. Vector clocks solve the concurrency problem.
